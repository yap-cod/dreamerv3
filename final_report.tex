\begin{abstract}
We present an \emph{exploratory, systems-style} study on DreamerV3~\cite{hafner2023dreamerv3} with Crafter~\cite{hafner2021crafter}: a controlled wood-linked reward bonus $\epsilon\in\{0,1,3,5\}$ induces a \emph{training-time proxy} that need not match native environment return. We organize results by \textbf{experiment family}---scalar Phase~1 baselines, static multi-objective (MO), dynamic MO, and scalar oracle shaping---rather than collapsing everything into one plot. Native Crafter aggregates are shown separately so cross-method comparisons are not confounded by different scalar training signals. We quantify a reproducible scalar \emph{proxy--true gap}
$\Delta$ between logged episode return and native reward sums, and report tail statistics (final 200k steps; single seed per configuration). We position this as \textbf{valid exploration research}: it isolates failure modes and mitigation tradeoffs in a modern model-based RL stack and states explicit limitations (single seed, operational $\Delta$, partial runs where noted).
\end{abstract}

\section{Motivation and research stance}
Model-based agents optimize long imagined rollouts against learned reward heads. When the training reward is misspecified or augmented, two questions arise: (i) do outcomes on \emph{native} environment telemetry remain sensible, and (ii) how large is the divergence between the \emph{proxy} objective (logging / training) and the \emph{native} return aggregate we care about for alignment?

This report answers these questions \emph{empirically and comparatively}, without claiming to isolate imagination error exclusively from generic dense-reward pathology.

\section{Interventions}
\subsection{Wood-linked perturbation}
\begin{equation}
\hat{r}_t^\epsilon=\hat{r}_t+\epsilon\cdot \mathbf{1}[\text{wood inventory increases}]
\end{equation}
\subsection{Architectural mitigations (MO)}
Vector reward $\vec{R}=[R_{\mathrm{hack}},\Delta hp,\Delta \mathrm{ach}]$ with Cobb--Douglas actor scalarization (static weights; dynamic health weighting in Phase~3B).
\subsection{Oracle scalar shaping}
Preference-shaped scalar return
\begin{equation}
\tilde{r}_t=r_t^\epsilon+\alpha\cdot \Delta \mathrm{achievement}_t,\quad \alpha=0.3,
\end{equation}
at $\epsilon\in\{1,5\}$.

\section{Operational metrics}
\subsection{Comparable native outcome}
Native Crafter telemetry uses \texttt{epstats/log/reward/sum} (episode aggregate of the game's own reward channel, prior to vector MO packaging). Native health uses \texttt{epstats/log/health\_level/avg}.

\subsection{Proxy--true gap (quantization)}
Define the \emph{operational gap} at logging time as
\begin{equation}
\Delta_t = \texttt{episode/score}_t-\texttt{reward\_sum}^{\mathrm{native}}_t
\end{equation}
where \texttt{episode/score} is the trainer's episodic scalar (includes wood bonus for $\epsilon{>}0$, and includes oracle shaping terms for oracle runs), while \texttt{reward\_sum}$^{\mathrm{native}}$ is the native aggregate from Crafter logs. Sparse trainer rows are merged with outer joins and mild forward-fill so curves exist on a common step axis (standard practice for episodic aggregates reported asynchronously).

\textbf{Caveats we will defend verbally:} (i)~$\Delta$ is not ``Bellman error''; it is a proxy alignment diagnostic. (ii)~Oracle runs intentionally inflate $\Delta$ because $\tilde{r}$ adds components not present in native sums---large oracle $\Delta$ is expected and must be read alongside native outcome panels.

\section{Discussion (what we can claim)}
\textbf{Structured comparison.} Splitting plots by experimental family mirrors how a serious systems paper groups ablations---it is not ``more images,'' it is \emph{legibility}.\\
\textbf{Native outcomes.} Oracle and MO runs should be judged on native reward/health panels, not on hacked score alone.\\
\textbf{Gap panel.} $\Delta$ is an explicit scalarization of ``how much the logged return drifts from native Crafter return under our interventions.'' It is most interpretable for $\epsilon{>}0$ wood hack; oracle rows are dominated by additional shaping and should be paired with Table~\ref{tab:gap} + native panels.\\
\textbf{Limitations.} Single seed per configuration; operational $\Delta$ definition; partial alignment of sparse logs; one dynamic run shorter.

\section{Conclusion}
This is best read as \textbf{exploration with measurement}: we built a controlled Crafter $\times$ DreamerV3 testbed, compared scalar, MO, and oracle mitigations, and separated \emph{native} outcomes from \emph{proxy} logging through $\Delta$. The scientific product is a reproducible experimental map plus honest limits---not a single headline number.

\appendix
\section*{Short Q\&A sheet (for presentation)}
\begin{itemize}[leftmargin=1.2em, itemsep=2pt]
  \item \textbf{Is this ``real'' reward hacking?} It is a \emph{controlled} misspecification of the training signal (wood bonus) in a real MBRL stack; we report both native outcomes and proxy gaps.
  \item \textbf{Why is oracle $\Delta$ huge?} Oracle adds terms to the training scalar that are not in native Crafter sums; large $\Delta$ is expected and is \emph{not} the same statement as large imagination error.
  \item \textbf{Why not one blob plot?} Different families use different internal reward packaging; native panels and family-separated gap panels keep comparisons honest and readable.
  \item \textbf{What would you do with more time?} Multi-seed bands, full 1M completion for all runs, and (if isolating ``imagination'' specifically) a model-free control or imagination-horizon ablation.
  \item \textbf{What is the strongest empirical takeaway?} MO reduces proxy--true pressure relative to scalar at matched $\epsilon$ in several rows; dynamic MO is best at high $\epsilon$ among completed runs; oracle is a cheap scalar intervention but changes the meaning of $\Delta$.
\end{itemize}
